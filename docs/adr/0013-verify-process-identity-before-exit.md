# Idle 退出前核对登记的进程身份

仅凭 `kill(pid, 0)` 不能证明 PID 仍属于登记的 Pi。异常退出留下的记录
可能在 PID 被复用后继续显示为 live；旧版 Idle 退出会直接向该 PID 发信号。

## 决定

保留自报注册表，不增加进程表、tmux 或会话目录的兜底扫描。

1. 扩展初始化时只为自身采集一次 `processIdentity`，随状态更新原样发布。
   Linux 使用 `/proc/sys/kernel/random/boot_id` 和 `/proc/<pid>/stat`
   第 22 字段 `starttime`（启动后的内核 tick）。面板行保留此身份。
2. Idle 退出严格解析正安全整数 PID，并读取该 PID 的最新注册记录。
   目录 PID 与记录 PID、所选行与记录的身份、会话文件、Idle 状态必须一致。
3. 最后重新读取目标的内核启动身份，与登记身份比较后同步发送 SIGTERM。
   不能只拿当前 PID 的身份替旧记录补登；旧行也不能授权新登记的同 PID Pi。
4. 缺失身份、记录损坏或消失、读取失败、进程消失/僵尸、身份不符，全部拒绝。
   失败由现有面板错误提示展示，不把会话插入 Closed。

`readRegistry()` 的存活结果仍只是便宜的列表提示，残留行可能继续可见；
它不赋予退出权限。定向读取一个已登记 PID 的 procfs 信息不是发现进程的扫描。
名称、cwd、tmux pane 或命令行里包含 `pi` 都不作为身份凭据。

## 平台与兼容性

- Linux：面板与目标处于同一 PID namespace，使用可读、与其一致的 procfs。
  `/proc` 缺失、权限限制或启动身份不可读时拒绝。注册表应是同一用户、同一主机
  的私有目录，不支持在不同容器/PID namespace 间共享它。
- macOS：本补丁有意拒绝 Idle 退出，列表及其余操作继续可用。没有新增原生依赖；
  不把 `ps lstart` 的秒精度时间当作可靠出生身份。后续真正启用需要原生
  `libproc` 启动信息，或带每实例凭据、由目标执行的控制通道。
- 旧记录没有身份时保留显示但拒绝退出；在支持的平台更新目标 Pi 并 `/reload`
  或重启后才登记。只更新面板宿主不够，不能从仍存活的未知 PID 推断旧身份。

## 边界与剩余竞态

启动身份确认的是自报 Pi 的进程生命周期，不认证可执行文件内容，也不防御
同权限用户伪造注册表。`execve` 在同一生命周期替换程序不会改变该出生标识。
内核 starttime 具有 tick 精度，因此也不宣称它是数学上绝对唯一的随机凭据。

最终身份查询和 `kill(pid, SIGTERM)` 不是原子操作。即使中间没有 `await`，
目标仍可能恰在两者之间退出并让 PID 被复用；Idle 状态也可能在查询后变化。
彻底消除 PID 信号竞态需持有并验证 pidfd 后使用 `pidfd_send_signal`，
或让已认证的目标实例自行退出。重复一次 `kill(pid, 0)` 无法解决它。
SIGTERM 成功返回只表示信号已发送，不证明 Pi 已结束或会话文件已干净收尾。

## 验证

新增的退出回归通过模拟进程身份和信号覆盖正常退出、残留记录、PID 复用、
新 Pi 覆盖同 PID 注册记录、旧格式、权限/解析错误、Idle/会话变更及信号错误。
测试断言拒绝分支没有 SIGTERM，正常分支只有一次且在身份验证之后。
实际 Linux procfs 可另做只读自进程探测，不需要向真实进程发信号。

本机仍需用可丢弃会话验证 Pi `/reload` 登记、实际 Idle 的 SIGTERM 收尾与
Closed 展示、受限 procfs 的提示，以及 macOS 的拒绝提示和其余面板功能。
模拟回归不代表曾在用户机器复现误停，也不证明上述 TOCTOU 已消失。
