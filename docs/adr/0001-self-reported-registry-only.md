# 只认自报注册表，不做任何兜底扫描

Session 的来源只有一个：每个 pi 实例在扩展加载时往 `~/.pi/agent/session-panel/registry/<pid>.json` 写自己的记录，状态变化时原子重写。面板 1 秒轮询读这个目录。

没有任何兜底：不扫 tmux 标题、不扫进程表、不扫 session 目录来补全。没写注册表的 pi 视同不存在。装了本包但早于安装就开着的 pi，要等到 `/reload` 才出现。

## Considered Options

- 混合（注册表 + 扫 tmux 标题兜底）：pi 的终端标题里有 `π - <name> - <cwd>`，可以知道"有个 π 在跑但没注册"。被否决，因为它只能给出存在性提示，给不出状态和 session 路径，会让列表出现一类半残条目。
- 纯扫描（tmux 标题 + 文件 mtime）：零配合，但 stopped 和 closed 根本分不开。

## Consequences

状态准确性和"看不见"的边界都变得完全可预测：看得见的一定在注册表里，看不见的一定没注册。代价是存在一个安装前的盲区，且这个盲区无法自动收敛。
