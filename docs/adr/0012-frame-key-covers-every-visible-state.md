# 面板的每一帧都先算完整，再取 key

帧缓存（`render` 命中就直接返回上一帧）的前提是「key 覆盖了所有会变的东西」。这一条被违反过两次，症状都是「按了键没反应」。

## 修掉的四处

| key 漏了什么 | 症状 |
|---|---|
| 光标位置 | rename 里按 ← → 屏幕纹丝不动，接着输入的字符却插在中间 |
| 帮助页开关 | 按 `?` 后看不到任何东西，而下一次按键被这个隐形页面吃掉 |
| 面板自己改的数据 | rename 成同长度的名字、或改名第 300 行之后的行，列表一直显示旧名 |
| `windowStart` 是渲染后才写的 | 每次滚动都多付一次整帧重建 |

前三个靠把字段补进 key 解决。第四个靠**先算后取**：`scrollIntoView()` 在 `frameKey()` 之前跑，key 描述的帧和实际画出来的帧才是同一个。

## 数据指纹为什么不够

`dataSignature()` 只采样前 300 行的几个数字（`updatedAt`、名字长度、状态长度），因为它每 50ms 跑一次，不能把 1976 个名字都哈希一遍。

「名字长度」这个字段是错的：rename 成等长的名字不改变它。补一个 `revision` 计数器，面板自己的动作（rename / delete / exit）成功后自增，直接进 key。比完整哈希便宜，而且精确覆盖了「面板改的」这一整类。

外部变化仍然靠采样：别的 pi 改了名、新会话出现，这些都会同时改动 `updatedAt` 或行数，采样能抓到。

## Consequences

key 里现在有 16 个字段，全拼起来是一条约 200 字节的字符串，每 tick 一次，成本可忽略（缓存命中仍是微秒级）。

新加任何可见状态时必须同时加进 `frameKey`。忘了就会重现「按键没反应」，而且这种 bug 不会报错，只会静默。
