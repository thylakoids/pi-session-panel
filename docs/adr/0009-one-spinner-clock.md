# 所有 working 行共用一个 spinner 时钟

面板里每一行 working 状态原本按自己的 key 哈希出一个相位偏移，各走各的呼吸节奏。改成整个面板共用一个时钟：`spinnerFrame(at)`，没有 `rowPhase`。

## 为什么不各走各的

Claude Code 的 spinner 是「一个对话一个」——同一时刻只可能有一个在转，不存在多行并排的情况，所以它那边没有「同步/不同步」这个问题。照抄它的缓动曲线（`Kn` 两秒、`qLe` 余弦、`Zn` 量化）却给它加上每行独立的相位，等于把一个为单实例设计的东西硬拆成多实例。

视觉上的后果不是「更丰富」，而是「散」：一列行在同一块面板里各自呼吸，读起来像几个互不相关的动画，而不是「这块面板里有工作在跑」。

## 之前为什么会这么写

上一版的注释写着「several sessions must not march in lockstep」。这个判断在当时是错的：锁步不是缺陷，它才是这类状态指示器的默认语义。真实的多实例 spinner（构建工具、任务队列）也普遍同步，因为用户读的是「整体是否在动」，不是逐行的相位。

## Consequences

`workingGlyphs()` 从「拼出每一行的字形」退化成「一个字形或空串」，frame key 的这部分成本从 O(working 行数) 变成 O(1)。没有 working 行时返回空串，key 保持稳定，缓存照常命中。

写测试时踩到一个坑：拿 `live:1` / `live:2` / `live:3` 当 key，它们的哈希相位是 1037 / 1036 / 1035，相差不到一个字形台阶，**旧代码也能通过**。必须用相位真正拉开距离的 key（真实 pid 形状，如 `live:11729` 相位 1744 与 `live:14002` 相位 321），断言才有鉴别力。这一点写进测试注释了。
