# 动画只付出字形真正变化时的代价

spinner 每 200ms 才换一帧，但面板原本每个 tick 都重建整个 frame。三层措施把它压到近乎免费：

1. **宿主层门控**：定时器 50ms 轮询 `currentGlyph()`，字形没变就不调 `tui.requestRender()`。60 秒内只请求 300 次重绘，而不是 1200 次。
2. **frame 缓存**：`render()` 先算一个 key（宽度、主题、选中、搜索、窗口起点、当前字形、秒级时间戳、数据指纹），命中就直接返回上一帧。命中成本 3.3µs。
3. **快速截断**：`truncateToWidth` 因为要切字素而耗时 6.9µs，而 `visibleWidth` 只要 0.5µs。先量宽度，放得下就直接返回。

## Consequences

1400 行时：重建一帧 1.62ms，缓存命中 3.3µs，平均每 tick 0.98ms。

这套做法依赖一个前提：面板的可变部分只有 working 行的图标和秒级时间戳。如果以后有行内容按亚秒变化（例如实时 token 计数），第 2 层的 key 必须跟着扩展，否则会显示陈旧数据。
