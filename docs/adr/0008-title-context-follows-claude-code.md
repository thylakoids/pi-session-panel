# 起名的 context 对齐 Claude Code

起名送进模型的 context，抄 Claude Code 2.1.304 的 `generate_session_title`（bundle 里的 `$Se`）。理由只有一个：这个面板的列表和 Claude Code 的会话列表是同一个东西，起名的用途完全相同——在一长串会话里认出某一个。

## 抄了什么

| | Claude Code | 之前 | 现在 |
|---|---|---|---|
| system prompt | 约 40 句，逐条封死一类坏标题 | 一句话，"6 words" | 同 Claude Code |
| 送什么内容 | 分支上**每一条**真人 user 消息 | 第一条消息的**第一行** | 每一条真人 user 消息 |
| 助手/工具文本 | 排除 | 排除 | 排除 |
| 内容长度上限 | 1000 字符，取尾部 | 无 | 1000 字符，取尾部 |
| 单条太长的处理 | 中间挖掉，标 `[… N characters omitted …]` | 不处理 | 同 Claude Code |
| 包装 | `<session>…</session>` + 语言指令 | `PROMPT\n\n---\n` + 原文 | 同 Claude Code |
| 语言 | 写在 user turn 里 | 写在 system prompt 里 | 写在 user turn 里 |
| 写入前 | 再查一次名字，已被设置就丢弃 | 不查 | 同 Claude Code |

### 为什么是「每一条 user 消息」

之前只取第一条消息的第一行。真实会话经常是「看下这个」+ 粘贴一段堆栈 + 「它为什么报这个」，第一行完全没有信息量。Claude Code 把分支上所有真人消息拼起来，正是为了这个场景。

助手文本和工具结果排除在外：前者是对提问的反应，后者是用户没写过的输出。

### 为什么中间挖掉而不是截断

粘贴的日志动辄几千行，用户真正的问题在**末尾**。保留头部丢掉尾部，等于给堆栈的第一帧起名。

### 为什么写入前要再查一次

模型在思考的几百毫秒里，用户可能已经手改了名字。覆盖手写的名字是这里唯一不可撤销的错误。

## 一处刻意不抄

Claude Code 用 `input.trim().length < 10` 判断消息是否值得起名。这是个英文阈值：10 个拉丁字符是一句碎片（"look at this"），而 9 个汉字已经是一整句问题（"滑点模型为什么偏高"）。直接抄会在中文下把所有正常提问挡在门外。

改成按信息量计：每个汉字/假名/谚文音节算 1，每段拉丁字母/数字算 1，阈值 3。这样"hi"（1）和"继续"（2）仍然被跳过，"滑点模型为什么偏高"（9）和"fix the bug"（3）都能进。

## Considered Options

- **照抄 10 字符阈值**：被否决，中文下等于关掉起名。
- **按 Unicode 码点算**：等价于照抄，只是把 10 换成别的数字，仍然是「长度」而不是「信息量」。
- **让模型自己判断值不值得起名**：被否决，那要花一次模型调用才知道该不该花这次调用。

## Consequences

system prompt 从 30 个词涨到约 400 个词，每次起名多花几百 input token。起名本来就只在会话第一次有消息时发生一次，这笔开销换来的是一整列表可读的名字。

`MIN_UNITS` 的 3 是估的，不是量出来的。如果发现太啰嗦的会话被起了名，或者该起名的被跳过，改这个数字，不要改判断方式。
